## ゲーム概要
組織の裏切りにより全てを失った主人公が、
旧式の人型兵器「Exo」を駆り、復讐へと向かうハイスピード3Dメカアクションゲーム

## コンセプト
高速機動による「爽快感」と、
「撃つ楽しさ」・「避ける楽しさ」を両立した戦闘体験


## 操作方法

* **W / A / S / D :** 機体の移動
* **Space (長押し) :** ジャンプ / ブースト上昇
* **Left Shift :** 回避アクション
* **R :** 武装のリロード
* **Tab :** ロックオンモード切り替え（ソフトロック ⇄ ハードロック）
* **マウスホイール :** 武器セットの切り替え
* **左クリック :** マシンガン、ショットガン
* **右クリック :** 旋回ミサイル、高高度ミサイル
* **F1 :** UIを非表示にする
* **F2 :** フリーカメラに切り替える
* **F3 :** プレイヤーに敵AIを乗せる(確認用)
* **ESC :** メニュー、一時停止

# 本作における技術的挑戦と設計アピール

## 1. スピード感を強調する遅延カメラ
* **ソース位置：** `\Game\Camera`

初期はカメラを機体へ完全固定していたため、
移動速度や急な加減速の変化が視覚的に伝わりにくい問題がありました。
そこで、カメラが少し遅れて追従する制御を実装し、
移動速度や高度差に応じて追従量を動的に変化させる仕様に変更しました。
これにより、左右移動や回避アクション時に機体が画面内をダイナミックに動くようになり、
**高速移動時の爽快感とスピード感を大幅に向上**させています。

---

## 2. 直感的な操作を実現するロックオン制御
* **ソース位置：** `\Game\Camera`、`\Game\Systems\LockOn`

単純な距離判定のみでターゲットを選出すると、
画面端の敵や意図しない対象にロックが移ってしまい、
狙いたい敵を選びづらいストレスがありました。
そこで、画面中央（レティクル）との距離や enemy との相対的な位置関係をスコア化し、
評価の高い対象を優先してロックオンするアルゴリズムを実装しました。
また、ロック中に一定以上の視点入力（手動操作）を検知した場合は、
自動追従を解除して手動操作へ移行する仕組みも導入しています。
結果として、プレイヤーの視線に近い敵を自然かつ直感的に捉えられるようになり、
**激しい空中戦でも快適なターゲット選択を実現**しました。

---

## 3. 回避のスリルを生み出すミサイル誘導制御
* **ソース位置：** `\Game\GameObjects\Projectile\Missile`

弧を描きながら迫る派手なミサイル軌道を目指したものの、
追尾性能（旋回力）を強くしすぎるとプレイヤーにとって「回避不可能な理不尽な挙動」になり、回避のタイミングが掴めなくなる課題が生じました。
これに対し、外積を利用して目標への旋回方向を計算しつつ、
フレームあたりの最大旋回角度に制限を設けるアプローチをとりました。
ミサイルが大きく回り込みながら追尾する美しい軌道を作り出し、
**プレイヤーが「引きつけてからダッシュで綺麗に回避できる」絶妙な緊張感とゲームとしての楽しさを両立**させています。

---

## 4. 戦況を見失わせないUIと情報設計
* **ソース位置：** `\Game\UI`

上下左右360度に広がる空中戦が主軸であるため、
画面外から迫る敵の位置や、
どの方向から攻撃（被弾）されているのかをプレイヤーが素早く把握しづらい問題がありました。
この解決のため、画面外の敵の位置・距離を外周にナビゲートする「レーダー機能」と、
ダメージを受けた際に攻撃元を視覚的に通知する
「被弾方向表示機能（ヒットインジケーター）」を実装しました。
これにより乱戦時でも敵の位置や攻撃方向を常に視覚的にキャッチできるようになり、
**プレイヤーが戦況を見失って混乱する場面を大幅に減少**させました。

---

## 5. 継承から保持への転換による機体共通化（コンポーネント化）
* **ソース位置：** `\Game\GameObjects\Robot`

当初は機体ごとにクラスを継承して固有機能を実装していましたが、
機能追加や仕様変更のたびに親クラスが肥大化・複雑化し、
拡張が困難な密結合状態に陥っていました。
そこで、基盤となる `Robot` を共通クラスとし、
機体の「状態」や「武器」をそれぞれ独立したコンポーネントとして保持する設計へ移行しました。
外部システムは `Robot` ポインタ1本を介するだけで全機体を制御可能となり、
複雑な相互参照を解消。
**仕様変更や機能拡張に柔軟に対応できる、コンポジション指向のクリーンな機体基盤を実現**しました。

---

## 6. 操作の独立と入力基盤の共通化
* **ソース位置：** `\Game\Systems\Input`

初期は自機クラス（Player）の内部で直接キー入力を監視していたため、
操作方法の切り替えや、AIによる自動操作への拡張が極めて困難でした。
操作命令を `IManipulator` インターフェースとして抽象化し、
実際の入力検知（コントローラークラス）を機体制御ロジックから完全に分離させました。
プレイヤー操作とAI操作を共通の入力命令（`RobotCommand`）として同一に扱えるようになり、
操作媒体の切り替えはもちろん、
**デバッグ用の「AI対AI戦闘」などのシミュレート環境を容易に構築できる強力な入力基盤**が完成しました。

---

## 7. 複数武器の管理と切り替えシステムの構築
* **ソース位置：** `\Game\GameObjects\Weapon`

ショットガンやミサイルなど、挙動やパラメータが全く異なる武器を追加していく際、
機体側に個別の武器処理を書き足していくと、
武器の切り替えや状態管理のコードがスパゲティ化する懸念がありました。
武器の共通処理（リロード、残弾管理、発射インターバル等）を最上位クラス `WeaponRuntime` へ集約し、
機体側がこのベースポインタ配列を保持・管理する構成を採用しました。
武器ごとの状態管理が完全に独立したことで、既存のシステムに一切影響を与えることなく、
**ショットガンや高高度ミサイル等の新しい武装を
同一の仕組みのまま容易に追加・切り替えできる高い拡張性を確保**しました。

```text

│  └─Weapon          < 各種武装の固有ロジック（複数武器の切り替え基盤）

├─Systems            < ゲームの実行を支えるコアシステム群
│  ├─Collision       < 当たり判定、ヒット・ダメージ処理
│  ├─Effect          < パーティクルや視覚エフェクトの生成・管理
│  ├─Input           < 入力の抽象化（IManipulatorによる命令駆動基盤）
│  ├─LockOn          < 標的選出AI、手動入力による自動追従解除
│  ├─Pause           < ゲームの一時停止・再開制御
│  └─Sound           < BGM・SEの再生管理
├─UI                 < 各種画面表示（HUD、メニュー、ステータス画面）の制御
└─World              < 全オブジェクトの生成・更新・描画ループの統括

```

## 今後の展望

### 1. 外部ファイル（CSV/JSON）によるデータ駆動化
現在は各種武装や機体のパラメータがC++のコード内に定数としてハードコーディングされています。
これらを外部ファイルから動的に読み込むデータ駆動型へと移行し、
プログラムを再ビルドすることなくゲームバランスの調整を行える、
より柔軟で実戦的な開発環境への刷新を目指します。

### 2. AI戦闘システムの高度化
現在実装しているAI対AI戦闘シミュレートをさらに発展させ、
より自然で安定した自律戦闘を実現します。
障害物検知や経路判断の改善により、
複雑な地形でも状況に応じた行動を継続できるAIへとブラッシュアップし、
デバッグ用途だけでなくゲームプレイ全体の品質向上にも繋げることを目指します。

### 3. コンポーネント設計を活かした機体バリエーションの拡張
コンポジション指向で構築した共通機体基盤（`Robot` クラス）の拡張性を検証するため、
パーツやパラメータの異なる「軽量高機動型」や
「重量高火力型」といった異なる特性を持つ機体バリエーションの実装を予定しています。
既存のシステム（状態遷移や武器管理）を汚すことなく、
コンポーネントの入れ替えだけで挙動をガラリと変えられる設計の強みを実証します。

### 4. 利便性を高めるオプションメニューの追加
プレイヤーの手触りや快適性を重視したゲームデザインの仕上げとして、
音量（BGM/SE）のシームレスな音量調整や、
プレイヤーごとの好みに応じたマウス感度の動的変更に対応するオプションシステムを実装します。
各マネージャークラスと連携し、ゲームプレイ中いつでもリアルタイムに変更が反映される仕組みを構築予定です。
